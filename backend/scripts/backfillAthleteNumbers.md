# 历史报名补号

先备份数据库，在维护时段执行。脚本使用 `backend/config/.env` 或进程环境中的 `MONGO_URI`，默认仅预览，显式 `--apply` 才写入。不得将数据库密码写进报告或提交到仓库。

从项目根目录进入一个用于存放迁移报告的目录，例如本地已忽略的 `.tmp`：

```powershell
New-Item -ItemType Directory -Force .tmp
Set-Location .tmp
node ../backend/scripts/backfillAthleteNumbers.js
node ../backend/scripts/backfillAthleteNumbers.js --apply
node ../backend/scripts/backfillAthleteNumbers.js
```

Linux 服务器同样进入专用报告目录，执行上述 `node` 命令。执行前确认预览显示的数据库名称与部署连接目标均正确。

规则：

- 覆盖所有赛事的未编号真实报名，跳过虚拟队伍及已编号记录。
- 同赛事、提交账号、单位、姓名、性别、出生日期和非空证件号码均一致时，共用编号；只存在一个完全匹配的现有人员编号时复用。
- 没有证件资料时按原记录分别编号，不按同名推断同人；这类人员如有多个项目，需要后续人工确认编号关联，避免费用人数误算。
- 账号、赛事、姓名或单位缺失时，该记录列入 exceptions 异常报告，保留原样；其余资料完整记录继续补号。已编号但关联失效的记录不在此脚本修复范围。
- 保存编号和更新时间，保留其他报名字段。每条报名采用原版本条件更新，出现冲突就停止；已完成部分保留，可在确认后重跑。人员身份 upsert 使用固定请求标识，重试不重复建号。
- 当前目录生成 `athlete-number-backfill-*.json` 变更报告；写入前先记录目标及原版本。报告应限制访问，不能提交仓库。中断后查看报告和当前数据再续跑，不要盲目删除人员编号。

应先完成业务库备份、执行补号并确认缺号为 0，再部署并重启新版后端及更新前端。编号必填校验一直保留；页面重新加载后使用最新编号。

本地执行结果：23 条真实报名补为 21 个编号，18 组无证件按记录独立分配；缺号 0，复跑待处理 0，其他业务字段快照一致。该结果仅属于本机 `competition_system`，远程服务器需单独执行。

异常记录不阻断正常补号。`registrations: 0` 表示可处理报名已清零；`unresolved` 表示仍需人工确认的数量。`remaining` 是全部缺号数，只有全部为0时 `completed` 才为 true；不得将异常记录误报为已完成。缺少账号的报名仍不能自行编辑。
