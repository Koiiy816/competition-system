# 武术报名项目编辑：使用与验收

## 开启方式

部署新版前后端后，管理员在「后台管理 → 系统安全设置」开启「允许参赛单位编辑武术报名项目」。配置键为 `wushu_registration_edit_enabled`，缺失时默认关闭，保存后新请求立即生效，无需重启。

参赛单位重新进入或切回「我的报名」页面即可刷新开关状态。名单及按项目分组视图均在删除按钮旁提供编辑入口。已经打开的编辑窗口在保存时仍会由后端重新验证开关和截止时间。

## 数据规则

- 独立接口：`PUT /api/competitions/:competitionId/participants/:id/registration-content`。
- 仅允许原提交单位账号修改武术报名，且比赛处于报名阶段、当前时间严格早于有效截止时间。
- 可提交字段为 `event`、`ageGroup`、`groupTeam`、`eventDetail`、`updatedAt`；其他字段拒绝接收。
- 原人员身份、所属单位、照片、报名编号和报名时间保留；同步更新年龄组/年级、项目分类及补充说明，清空原人工分组，状态回到待审核。
- 已检录、缺席、关联赛程/成绩/虚拟集体队伍的记录拒绝自行修改，交管理员处理。
- 校验项目归属、组别、出生日期、性别、补充说明、集体队伍编号、目标项目重复报名及原有罗湖赛事报名限制。
- `updatedAt` 与状态参与条件更新，避免同一记录被并发保存覆盖；冲突返回 409。管理员通用修改也更新此时间。
- 武术单位的旧通用编辑入口拒绝使用，防止绕过开关；其他赛事原有待审核编辑、管理员编辑、新增、删除、审核保持可用。
- 开关影响新请求；已经通过开关检查的在途请求不具备跨集合事务取消保证。并发修改赛事配置、生成赛程与报名编辑之间没有新增全局事务锁。

## 浏览器验收步骤

以下为交付后的浏览器验收用例，本次未执行浏览器自动化：

1. 管理员开启开关；参赛单位在截止前进入「我的报名」，确认已通过记录的删除按钮旁显示编辑。
2. 更换合法项目并保存，确认显示新项目和待审核，名单与项目分组均刷新；报名编号与人员身份不变。
3. 集体项目填写队伍编号；要求项目说明的项目不填写说明时应保存失败。
4. 同时打开两份同一报名，先保存一份，再保存另一份，应提示刷新重试。
5. 保持编辑窗口打开，管理员关闭开关，再保存应被拒绝；新增报名、删除、审核与管理员编辑仍可操作。
6. 截止后或进入比赛阶段，编辑入口不再提供；直接请求编辑接口也被拒绝。
7. 已编排或产生比赛数据的记录，保存时提示联系管理员。
